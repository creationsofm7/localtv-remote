How do I stop my phone remote disconnecting?

Keep LocalTV Remote running on the PC, keep both devices on the same stable LAN, and reopen the current controller address after the PC, router, or selected network changes.

Identify which connection ended

SymptomWhat it meansWhat to do
“Reconnecting…” appears brieflyThe phone UI lost its WebSocket and is retrying.Wait through a retry, keep the tab active, and verify Wi-Fi remains connected.
It repeatedly stays disconnectedThe PC server or network path is unavailable.Open the PC app and load the current displayed address again.
The PIN screen returnsThe saved browser token was unavailable or rejected.Enter the PIN shown on the PC. Private browsing, cleared site data, or a different browser profile will not share the old token.
It disconnects after a long idle periodThe server closes authenticated clients after 30 minutes without control activity.Reconnect from the controller; do not assume a session is kept indefinitely.

Stabilize the connection

  1. Prevent the PC from sleeping during use. When Windows sleeps, stops the process, or signs out in a way that ends LocalTV Remote, the phone cannot maintain the connection.
  2. Avoid switching the phone between Wi-Fi and mobile data. LocalTV Remote is LAN-only. Disable aggressive Wi-Fi switching for the session if the phone keeps preferring mobile data when the signal weakens.
  3. Keep both devices off guest Wi-Fi. Client isolation can interrupt or completely block device-to-device traffic even when both devices show the same network name.
  4. Use the current address after a restart. The PC’s local IP can change, and the daemon may select another port if 6776 is busy. Reopen the pairing window instead of relying on an old bookmark.
  5. Check firewall and security software. Permit the program on the trusted Private network. Do not disable the firewall or expose the app broadly on Public networks.
Retry is not guaranteed resume: after one successful authentication, the phone UI schedules reconnect attempts with exponential delays capped at 10 seconds. The server separately keeps trusted sessions only in the running process. Restarting LocalTV Remote clears those in-memory sessions, so automatic resume may fail and require the displayed PIN again.

The connection also uses plain HTTP and WebSocket on the local network rather than encrypted transport. Use a trusted LAN; improving signal quality does not add encryption.
